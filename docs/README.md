# VetClinic Management System - Детальна документація

Консольний додаток на C# для управління записами на прийом до ветеринара, медичними записами пацієнтів і графіком роботи ветеринарних лікарів.

## 📋 Огляд проєкту

**VetClinic** — об'єктно-орієнтований міні-проєкт, який демонструє чисту архітектуру, принципи SOLID та паттерни багатошарової архітектури на C#. Програма керує:
- Власниками тварин та їх інформацією
- Твариною (тваринами) з видами, породами та контролем віку  
- Ветеринарними лікарями та їх спеціалізацією
- Записами на прийом з перевіркою доступності
- Медичними записами (підготовлено для майбутніх ітерацій)

## 📱 Консольний додаток - Головний вертикальний зріз

Програма надає інтерфейс на основі меню:

```
1. Записати на прийом
   - Виберіть тварину зі списку пацієнтів клініки
   - Виберіть доступного ветеринара
   - Введіть бажану дату та час запису
   - Вкажіть причину відвідування
   - Система перевіряє доступність та створює запис

2. Переглянути всі записи
   - Відображає всі заплановані записи

3. Переглянути записи тварини
   - Показує всі записи конкретної тварини

4. Переглянути записи ветеринара
   - Показує всі записи конкретного ветеринара

5. Вихід
```

**Шлях вертикального зрізу:**
```
Введення користувача (Console) 
  → ClinicApp (UI організація)
    → AppointmentService (Бізнес-логіка)
      → Правила домену (Appointment, Pet, Veterinarian перевірка)
        → InMemoryAppointmentRepository (Збереження даних)
          → Вивід в консоль
```

## ✅ Реалізовані функції (Ітерація 1)

### Доменна модель (8 класів + 2 enums)
- ✅ **Owner**: Інкапсульовані властивості, перевірка email/телефону
- ✅ **Pet**: Контроль віку, дані на основі виду, відношення до власника
- ✅ **Veterinarian**: Спеціалізація, контроль ліцензії
- ✅ **Appointment**: Перевірка майбутньої дати, контроль статусу, переходи стану
- ✅ **MedicalRecord**: Посилання на завершені записи (основа для Lab 35)
- ✅ **Species & AppointmentStatus**: Enums для безпеки типу

### Бізнес-логіка
- ✅ **AppointmentService**: Запис, перегляд, завершення, скасування записів
- ✅ **Паттерн Result**: Функціональна обробка помилок (Success/Fail з повідомленнями)
- ✅ **Доступність ветеринара**: Запобігання подвійному бронюванню

### Обробка помилок
- ✅ Перевірка інваріантів домену (конструктори захищають від невірних станів)
- ✅ Перевірка правил бізнесу в сервісах
- ✅ Зручні повідомлення про помилки для користувачів
- ✅ Паттерн Result + винятки використовуються відповідно

### Тестування
- ✅ **15+ Юніт-тестів** що охоплюють:
  - Інваріанти доменної моделі (Owner, Pet, Veterinarian, Appointment)
  - Бізнес-логіку (AppointmentService)
  - Операції репозиторію
  - Крайні випадки (минулі дати, нульові значення, конфлікти)

## 🎓 Концепції OOP та SOLID (застосовані)

| Концепція | Реалізація |
|---------|-----------------|
| **Інкапсуляція** | Приватні setter'и, перевірка властивостей |
| **Спадкування** | (Підготовлено для Lab 35: базовий клас Person для Owner/Vet) |
| **Поліморфізм** | Інтерфейс IAppointmentRepository + реалізація |
| **Абстракція** | Паттерн Repository, доменні інтерфейси |
| **Single Responsibility** | Кожен клас має одну причину для змін |
| **Open/Closed** | Легко розширюється новими реалізаціями репозиторію |
| **Liskov Substitution** | InMemoryAppointmentRepository може замінити будь-який IAppointmentRepository |
| **Interface Segregation** | Фокусований контракт IAppointmentRepository |
| **Dependency Inversion** | Сервіси залежать від абстракцій (IAppointmentRepository) |
| **LINQ** | Використовується для запитів записів за твариною/ветеринаром |
| **Generics** | Result<T>, List<T>, IReadOnlyList<T> |
